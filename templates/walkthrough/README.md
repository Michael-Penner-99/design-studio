# Sales walkthrough template

`templates/walkthrough/walkthrough.html.template` is a single-file HTML walkthrough page that ships alongside every contractor site. It's the page the lead opens after Action Studio sends them their preview link — designed to argue the case for the rebuild in plain English while pointing back at the live site.

The walkthrough is generated by the proposal-writer agent in **Phase 7 (SOP 13)** and deployed to its own Vercel project at `{slug}-sales.actiondesignstudio.com` in **Phase 8 (SOP 14)**.

---

## Visual DNA

- **Theme:** light (cream `#F7F2EA` background, ink `#0A0A0A` body), distinct from the dark contractor sites.
- **Type:** Inter for body, Space Grotesk for headings. Loaded via Google Fonts CDN.
- **Accent:** red-orange gradient `linear-gradient(135deg, #FF4D2E, #E63312)` on every CTA and the lever numerals.
- **Header bar:** black `#0A0A0A` so the Action Studio mark and the contractor logo both pop.
- **Tailwind:** via CDN (no build step). Matches the pattern used by the contractor pages, but with a separate config block.

The visual reference is the King Contractor Agency Vercel page Michael shared. Same vibe — bold headlines, big numerals, expandable HOW? blocks, side-by-side cards.

---

## Page sections (top to bottom)

1. **Header bar** — Action Studio mark left, "PREPARED EXCLUSIVELY FOR: {{contractor_brand_name}}" + logo right.
2. **AI-photo banner** — conditional, name-and-reviews mode only.
3. **Hero** — "Here's why your website is leaving money on the table." + primary CTA → `{{site_preview_url}}`.
4. **The opportunity** — single-paragraph gap analysis pulled from `research/competitors.md`.
5. **The Winning Formula** — the centerpiece. Three cards (TRAFFIC / TRUST / CONVERSION) with `<details>` HOW? expanders. The HOW? copy is **hard-coded** — same sales script across every client.
6. **The proof** — three columns of customized review/photo/SEO evidence.
7. **What you're getting** — ten-item static checklist.
8. **The investment** — Standard ($5K) vs Pro ($15K) tier cards. Prices tokenized.
9. **Side-by-side comparison** — old site score vs new site score (both 0-120).
10. **CTA band** — "Schedule the cutover call" → `{{calendar_url}}`.
11. **Footer** — Action Studio mark, prepared date, copyright.

## Tokens

Standard single-curly-brace token syntax, matching the rest of the factory templates. Token resolution happens at proposal-generation time (SOP 13), reading from `clients/{slug}/brief.md` frontmatter, `evidence/reviews.json`, `research/site-scorecard.md`, and `deploy/preview-url.txt`.

| Token | Source | Example |
|---|---|---|
| `{{contractor_brand_name}}` | `brief.md` → `brand_name` | "Capstone Contracting" |
| `{{contractor_logo_path}}` | copied from `assets/processed/logo.png` to `sales/assets/logo.png` | `assets/logo.png` |
| `{{prepared_date}}` | run timestamp, formatted | "May 18, 2026" |
| `{{opportunity_summary}}` | 2-3 sentence pull from `research/competitors.md` | "Your top 3 competitors all rank for..." |
| `{{primary_keyword}}` | `strategy/keywords.md` → primary keyword | "Kansas City roof repair" |
| `{{review_count}}` | `evidence/reviews.json` → total count | `127` |
| `{{review_rating}}` | `evidence/reviews.json` → avg rating | `4.8` |
| `{{photo_count}}` | count of files in `assets/processed/` matching `project-*` | `14` |
| `{{old_site_score}}` | `research/site-scorecard.md` → total | `48` |
| `{{new_site_score}}` | `qa/report.md` → final score | `112` |
| `{{site_preview_url}}` | `deploy/preview-url.txt` | `https://capstone-contracting.actiondesignstudio.com` |
| `{{calendar_url}}` | env var or default | `mailto:hello@actiondesignstudio.com` |
| `{{standard_tier_price}}` | spec override or recipe default | `$5,000` |
| `{{pro_tier_price}}` | spec override or recipe default | `$15,000` |

## Conditionals (new templating syntax)

The walkthrough introduces conditional blocks. Syntax:

```
{{#if_<condition>}}...{{/if_<condition>}}
```

Supported conditions (v1):

| Condition | True when |
|---|---|
| `if_mode_url` | `brief.md` frontmatter has `_meta.mode: url` (default for URL-mode runs) |
| `if_mode_name_and_reviews` | `brief.md` frontmatter has `_meta.mode: name-and-reviews` |
| `if_standard_tier` | run was triggered with `standard_tier=true` (default) |
| `if_pro_tier` | run was triggered with `pro_tier=true` |

The resolver behavior is documented in `docs/architecture.md` §3 (templating). The resolver:

1. Walks the template top-to-bottom.
2. For each `{{#if_X}}...{{/if_X}}` block, evaluates condition X against the run context.
3. If true → keeps the inner content (with all inner tokens resolved as normal).
4. If false → strips the entire block out, then continues.

Conditionals **do not nest** in v1. Each conditional is a flat pair on the same nesting level. If you need both `if_pro_tier` and `if_mode_name_and_reviews` to apply, write the inner content twice.

## Where the rendered output lands

Per-client folder, after Phase 7 (Proposal):

```
clients/{slug}/sales/
├── index.html                # the rendered walkthrough
└── assets/
    └── logo.png              # copied from assets/processed/logo.png
```

`scripts/new-client-from-name.sh` creates the `sales/` directory at scaffold time. `scripts/new-client.sh` (the URL-mode scaffold) creates it lazily inside SOP 13.

---

## Expected inputs (when the proposal-writer runs)

Before SOP 13 resolves this template, these files must exist and be valid:

- `clients/{slug}/brief.md` with all frontmatter populated
- `clients/{slug}/research/competitors.md`
- `clients/{slug}/research/site-scorecard.md` with a `total_score:` field
- `clients/{slug}/evidence/reviews.json` with `count` and `rating` fields
- `clients/{slug}/strategy/keywords.md` with a `primary_keyword:` field
- `clients/{slug}/qa/report.md` with a final score
- `clients/{slug}/deploy/preview-url.txt`
- `clients/{slug}/assets/processed/logo.png` (or `logo.svg`)

If any of those are missing, the proposal-writer halts and surfaces the missing input.

## Editing notes

- The HOW? copy in the three lever cards is universal — do not tokenize, do not customize per client. It's the same sales script every time on purpose; clients see this once and we want it tight.
- Pricing is the only commercial lever that varies. Override per spec via the queue contract's `options.standard_tier_price` / `options.pro_tier_price` (TBD — currently hard-defaulted in SOP 13).
- The dark contractor-site theme uses Anton + Montserrat + metallic golds. This template deliberately does **not** match — it's an Action Studio artifact, not a contractor artifact, so the visual language is different on purpose.
